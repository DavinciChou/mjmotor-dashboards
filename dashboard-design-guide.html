面板是什麼？能做什麼？

「營業數據面板」是一個網頁版即時報表，用瀏覽器打開就能看到銘勁汽車的銷售關鍵數據。它不需要安裝任何軟體，只要有公司帳號就能登入查看。

面板的目標是把散落在 Salesforce 裡的有望客戶資料，濃縮成一目瞭然的數字和圖表，讓主管和業務同仁能快速掌握：

本月業績

本月訂單數、領牌數、上月殘留待交車的 BO 數量

客戶動態

本週/本月新增了多少有望客戶，和上期相比成長或衰退

三店對比

八德、中壢、桃園各展示中心的訂單、領牌與新增客戶

商機分析

帳齡分布、客戶來源、客戶熱度（H/A/B/C 級）、車款偏好

趨勢追蹤

近 8 週每週新增有望客戶的折線趨勢圖

歷史累積

全部有望客戶統計、銷售漏斗、近 12 個月訂單 vs 成交趨勢

網址
面板部署在 GitHub Pages：https://davincichou.github.io/mjmotor-dashboards/

資料從哪裡來？

面板顯示的每一個數字，最終源頭都是 Salesforce（SF） 裡的「有望客戶」（Opportunity）資料。但面板不是直接連到 Salesforce 取資料，中間還經過一道「搬運」流程。整體流程如下：

Salesforce
有望客戶（原始資料）
→
Dataverse
Power Apps 資料表（副本）
→
GitHub Pages
面板網頁（index.html）
→
使用者瀏覽器
登入後即時顯示

為什麼不直接從 Salesforce 讀？

Salesforce 的 REST API 有嚴格的跨域（CORS）限制，從外部網頁無法直接呼叫。因此我們採用「中繼站」策略：透過 Power Apps 的 Dataflow，定時將 Salesforce 的有望客戶資料同步到 Microsoft Dataverse。面板再從 Dataverse 查詢資料，Dataverse 的 API 允許網頁端直接呼叫。

同步頻率
Dataflow 設定為每小時自動同步，使用增量刷新（Incremental Refresh），只更新最近 7 天內有異動的資料。如果有更早的資料異動，需要手動觸發「Full Refresh」。

系統架構全景

整個系統分成四層，每一層各有專責：

資料源
Salesforce CRM 有望客戶物件，約 23,000 筆紀錄
資料中繼
Power Apps Dataflow Dataverse 資料表 每小時增量同步，Standard 資料表（非虛擬表）
前端呈現
GitHub Pages 單一 HTML 檔 MSAL.js v2 認證 純前端，不需後端伺服器
身份驗證
Azure AD / Entra ID Dataverse 安全角色 每位同仁用自己的公司帳號登入，權限各自獨立

整個面板只有一個 HTML 檔案（index.html），裡面包含所有的畫面排版（HTML）、視覺樣式（CSS）和資料查詢邏輯（JavaScript）。這個設計的好處是部署和維護非常簡單——只需更新一個檔案。

Dataverse

微軟的雲端資料庫，屬於 Power Platform 的一部分。可以把它想成雲端版的 Excel 大表格，但效能更好、支援 API 查詢。

Dataflow

Power Apps 裡的「資料搬運工」，負責定時把 Salesforce 的資料複製一份到 Dataverse。類似排程的 ETL（擷取-轉換-載入）。

GitHub Pages

GitHub 提供的免費靜態網站服務。把 HTML 檔案推送到 GitHub，它就會自動變成可瀏覽的網頁。

MSAL.js

微軟的登入套件（JavaScript 版），讓網頁可以使用公司的 Microsoft 帳號進行身份驗證，取得存取 Dataverse 的授權。

查詢邏輯解說

面板透過 Dataverse 的 REST API 來計算各項數字。每次載入頁面時，會發出多筆 API 呼叫，同時（並行）查詢不同指標。以下用白話解釋每個數字的查詢邏輯：

本月業績三大卡

指標查詢邏輯（白話）對應 Salesforce 報告
本月訂單 「訂購日」落在本月的筆數 MJ面板A
本月領牌 「開立發票日」落在本月的筆數（不需判斷是否成交） MJ面板B（只看開立發票日，不加 iswon 條件）
上月殘留 BO 訂購日在本月之前、有下過訂、但尚未結案的筆數 —

以下是「本月訂單」的實際查詢範例，幫助理解語法：

// 查詢本月訂單數量 // start = 本月1日, end = 下月1日（例如 2026-03-01 到 2026-04-01） // sf = 營業所篩選條件（若選「全部」則為空字串） dvCount(`cre39_orderdate__c ge ${start} and cre39_orderdate__c lt ${end}${sf}`) // 翻譯：計算「訂購日 ≥ 本月1日 且 訂購日 < 下月1日」的筆數 // ge = greater than or equal（大於等於） // lt = less than（小於）

客戶數據

指標查詢邏輯
本週新增 「建立日期」落在本週一到明天的筆數（用明天零點做上限，避免查到未來日期）
本月新增 「建立日期」落在本月的筆數

兩者都會和前一期（上週 / 上月）比較，算出成長或衰退百分比。

每週趨勢圖

取近 8 週的每週新增客戶數，每週定義為「週一至週日」。當週的結束時間以「明天零點」為上限，避免查到未來日期。折線圖的 X 軸 label 顯示的是該週的週日日期。

認證與權限

面板的安全機制基於 Microsoft 的身份驗證系統（Azure AD / Entra ID），搭配 Dataverse 的安全角色。每位使用者需要具備兩項條件才能正常使用：

🔑
Microsoft 帳號
銘勁公司帳號
xxx@mjmotor.com.tw
＋
🛡
Dataverse 安全角色
營業數據面板 - 讀取者
（Organization 層級 Read）
＝
✅
可以看到數據
面板正常顯示所有數字

運作原理：使用者點擊「登入」按鈕後，MSAL.js 會引導到微軟的登入頁面。登入成功後，瀏覽器會拿到一個 Access Token（存取權杖），之後每次向 Dataverse 查詢資料都會帶上這個 Token。Dataverse 收到 Token 後會檢查「這個人有沒有讀取 cre39_sf_opportunities 資料表的權限」，有的話就回傳資料，沒有的話回傳 403 錯誤。

如果同仁看到面板全部是 0 或紅色錯誤訊息：表示該帳號缺少 Dataverse 安全角色。管理員需要到 Power Platform 管理中心，將「營業數據面板 - 讀取者」角色指派給該使用者。

安全角色管理路徑
Power Platform 管理中心 → 環境 → 銘勁汽車（default）→ 設定 → 使用者 → 搜尋使用者 → 管理角色 → 勾選「營業數據面板 - 讀取者」→ 儲存

部署與更新流程

面板的原始碼托管在 GitHub 上，修改後推送到 GitHub 就會自動更新網頁。流程如下：

本機修改
編輯 index.html
→
Git Push
推送到 GitHub
→
自動部署
GitHub Pages 更新

Git 推送指令：由於檔案存放路徑包含中文（OneDrive 資料夾），推送時使用短路徑格式的 .bat 批次檔執行 git push origin master:main（本機分支為 master，遠端為 main）。

修改面板的步驟：

1. 開啟 index.html 進行修改
2. 在本機瀏覽器開啟檔案預覽效果（需登入才能看到資料）
3. 確認無誤後執行 git push 推送
4. 等待 1-2 分鐘，GitHub Pages 自動部署完成
注意事項
面板是單一 HTML 檔案，所有 CSS、HTML、JavaScript 都在同一個檔案裡。修改時要小心不要破壞 HTML 標籤的配對（例如 <div> 和 </div> 要成對）。建議修改前先備份一份。
